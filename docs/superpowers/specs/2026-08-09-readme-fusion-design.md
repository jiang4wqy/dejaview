# DejaView README 融合版设计

日期：2026-08-09

状态：已获用户口头确认，等待书面规格复核

## 目标

将旧版 README 更有感染力的项目故事和完整图片叙事，与当前版本准确、可执行的开源技术文档融合。调整仅涉及中文 `README.md`，不修改产品代码、界面或部署配置。

## 成功标准

1. README 首屏恢复“项目照妖镜”、名称含义和鲜明的三人格定位。
2. `logo.png`、`flood.jpg`、`mirror.jpg` 与三张主题截图全部得到清晰、不过度重复的展示。
3. 访客能依次理解问题背景、产品价值、工作方式、实际效果和启动方法。
4. 当前版本的准确命令、安全边界、架构说明、项目状态和开源协作入口全部保留。
5. 不恢复固定测试数量、“Render 永久免费”等过时或无法持续验证的承诺。
6. 所有本地图片和文档链接有效，Markdown 结构可在 GitHub 正常渲染。

## 内容结构

README 按以下顺序组织：

1. Hero、Logo、项目名称、名称含义、核心口号、语言与文档入口、CI 与许可证徽章。
2. AI 时代项目泛滥的背景故事，配 `flood.jpg`。
3. “这不就是 XXX 吗？”的用户痛点，以及 DejaView 希望提前避免的尴尬。
4. “它会做什么”：用“项目照妖镜”解释产品，配 `mirror.jpg` 和四步能力说明。
5. 三种人格展示：镀金、毒舌、彩虹三张真实界面截图，并强调共享同一事实层。
6. 产品差异与可信边界：证据可追溯、缺信息降置信度、事实与语气分离。
7. 工作流程 Mermaid 图和与普通 AI 锐评工具的对比表。
8. mock 快速启动、真实分析模式、验证命令、架构目录、项目状态与许可证。

## 图片策略

本轮不新增 AI 插画。现有七张图片已经覆盖品牌、问题、产品比喻和实际界面：

- `hero.jpg`：三种人格的总体视觉；
- `logo.png`：品牌标识；
- `flood.jpg`：AI 应用泛滥的背景；
- `mirror.jpg`：“项目照妖镜”的产品比喻；
- `world-serious.png`、`world-roast.png`、`world-comfort.png`：真实结果页展示。

未来若补图，优先增加真实首页输入界面截图或短 GIF，形成“输入 → 分析 → 三种报告”的产品路径；不使用 AI 生成图代替真实界面。

## 保留与取舍

保留当前 README 中经过验证的内容：

- 中英文入口、架构、部署和贡献链接；
- CI 与 MIT 徽章；
- mock 零成本启动和真实 provider 配置；
- 安全提醒、验证命令、目录说明和项目状态；
- “统一事实层，语气会变，事实不会变”的核心不变量。

从旧版恢复并按当前事实校准：

- AI 时代背景故事；
- “这不就是 XXX 吗？”场景；
- “项目照妖镜”比喻及四步能力说明；
- 三人格的更鲜明文案和全部展示图片。

不恢复：

- 固定测试数量等容易过期的数字；
- “永久免费”等第三方平台承诺；
- 与当前部署、安全或功能状态冲突的旧说明；
- 已由部署文档覆盖的大段重复配置。

## 验证方法

1. 检查 `README.md` 中引用的每个本地文件均存在。
2. 检查相对 Markdown 链接指向现有文档。
3. 核对启动与验证命令仍与仓库脚本、依赖和当前目录一致。
4. 检查 Git diff，确保除设计说明和 `README.md` 外没有无关改动。
5. 在推送前向用户逐项说明实际修改内容，并等待成稿确认。
